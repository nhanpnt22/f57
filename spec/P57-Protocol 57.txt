============================================================
ABSTRACT
============================================================

P57 defines a minimal, invariant, and secure protocol for
transporting API request parameters as authenticated tokens.

P57 encodes request intent into a single canonical,
tamper-evident token using deterministic binary encoding
and cryptographic authentication.

P57 ensures:

- deterministic encoding
- strong integrity
- request binding
- replay protection

============================================================
STATUS OF THIS MEMO
============================================================

This document is provided for informational purposes and
is intended for production use.

============================================================
1. DESIGN PRINCIPLES
============================================================

P57 MUST:

- be minimal and invariant
- enforce deterministic encoding
- bind full request intent
- enforce security by default

P57 MUST NOT:

- allow algorithm negotiation
- include optional security features
- depend on ambiguous serialization (e.g., JSON)
- include redundant metadata

============================================================
2. DEPENDENCIES
============================================================

P57 depends on:

- B57 (canonical encoding)
- S57 (key derivation)
- H57 (hash / MAC)

Requirements:

- MAC MUST use H57
- H57 MUST use BLAKE3 keyed mode (256-bit)

============================================================
3. TOKEN STRUCTURE
============================================================

token = b57_encode(binary_token)

binary_token = version || payload || mac

------------------------------------------------------------
3.1 VERSION
------------------------------------------------------------

- size: 1 byte
- value: 0x01

MUST be validated.

------------------------------------------------------------
3.2 PAYLOAD
------------------------------------------------------------

payload = canonical_binary(params)

Requirements:

- MUST be deterministic
- MUST fully represent request intent
- MUST NOT include randomness

------------------------------------------------------------
3.3 MAC
------------------------------------------------------------

mac = H57(
  P57_KEY,
  "P57/v1" || version || payload
)

Properties:

- fixed size: 32 bytes (256-bit)
- MUST include domain separation
- MUST include version and payload
- MUST be verified before payload parsing
- MUST use constant-time comparison

============================================================
4. KEY DERIVATION
============================================================

P57_KEY = BLAKE3_DERIVE_KEY(
  server_secret_key,
  environment_salt,
  "S57/P57_KEY/v1",
  32 bytes
)

Requirements:

- MUST be secret
- MUST be isolated from other keys

============================================================
5. CANONICAL PAYLOAD
============================================================

params = {
  method    : string,
  path      : string,
  ts        : uint64,
  nonce     : bytes,
  client_id : string,
  body_hash : bytes (optional)
}

------------------------------------------------------------
5.1 FIELD ORDER (STRICT)
------------------------------------------------------------

method || path || ts || nonce || client_id || body_hash

No deviation allowed.

------------------------------------------------------------
5.2 TYPE ENCODING
------------------------------------------------------------

STRING:
 [len:uint32 BE] || UTF-8 bytes

UINT64:
 8 bytes (big-endian)

BYTES:
 [len:uint32 BE] || raw bytes

OPTIONAL body_hash:
 [present:uint8]
   0x00 → absent
   0x01 → encode as BYTES

------------------------------------------------------------
5.3 FULL ENCODING
------------------------------------------------------------

payload =

 encode_string(method)    ||
 encode_string(path)      ||
 encode_uint64(ts)        ||
 encode_bytes(nonce)      ||
 encode_string(client_id) ||
 encode_optional(body_hash)

------------------------------------------------------------
5.4 CANONICAL INVARIANT
------------------------------------------------------------

encode(decode(x)) == x

Implementations MUST reject non-canonical encodings.

============================================================
6. ENCODE / DECODE
============================================================

ENCODE:

 token = b57_encode(version || payload || mac)

DECODE:

1. binary = b57_decode(token)

2. parse:
   - version (1 byte)
   - mac (last 32 bytes)
   - payload (remaining bytes)

3. validate version

4. recompute MAC

5. verify MAC (constant-time)

6. decode payload

Requirements:

- MUST fail closed
- MUST NOT parse payload before MAC verification

============================================================
7. API
============================================================

p57 = new P57({
  server_secret_key,
  environment_salt
})

token = p57.encode(params)

params = p57.decode(token)

============================================================
8. REQUEST BINDING
============================================================

Server MUST verify:

- method matches HTTP method
- path matches endpoint

If body_hash is present:

 body_hash == H57(
   P57_KEY,
   "P57/BODY/v1" || raw_body
 )

============================================================
9. REPLAY PROTECTION
============================================================

Server MUST:

- enforce timestamp window (e.g., ±300 seconds)
- enforce nonce uniqueness

Nonce scope:

 uniqueness = (client_id, time_window)

Nonce MUST:

- be unique
- be unpredictable

Nonce SHOULD:

- be generated using R57 (≥128-bit entropy)

============================================================
10. TRANSPORT
============================================================

RECOMMENDED:

POST /endpoint
{
  "p57": "<token>"
}

ALTERNATIVE:

Header:
  X-P57: <token>

Requirements:

- MUST use HTTPS
- MUST NOT expose token via query string

============================================================
11. VALIDATION
============================================================

Valid token MUST:

- be valid B57
- decode to valid structure
- match version
- pass MAC verification

============================================================
12. ERROR MODEL
============================================================

Defined errors:

- INVALID_CHAR
- INVALID_STRUCTURE
- INVALID_VERSION
- AUTH_FAILURE

Requirements:

- MUST be deterministic
- MUST fail closed

============================================================
13. SECURITY CONSIDERATIONS
============================================================

P57 provides:

- integrity
- authenticity
- request binding

P57 does NOT provide:

- confidentiality (MUST use HTTPS)

DOMAIN SEPARATION:

All H57 usage MUST include domain separation:

 "P57/v1"
 "P57/BODY/v1"

Security depends on:

- secrecy of P57_KEY
- correctness of implementation
- CSPRNG quality (for nonce)

============================================================
14. LIMITS
============================================================

Implementations SHOULD enforce:

- method ≤ 16 bytes
- path ≤ 256 bytes
- client_id ≤ 64 bytes
- nonce ≥ 16 bytes

============================================================
15. INVARIANTS
============================================================

- token is canonical
- token is deterministic
- request intent == signed payload

============================================================
16. RELATIONSHIP TO STACK
============================================================

- B57 → encoding
- H57 → MAC
- R57 → randomness
- ID57 → identity
- S57 → cryptographic layer
- P57 → protocol
