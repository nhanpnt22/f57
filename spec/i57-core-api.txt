============================================================
ABSTRACT
============================================================

I57 defines a canonical integration layer for B57, H57,
R57, and ID57. It standardizes composition behavior,
validation semantics, and interoperability invariants.

I57 keeps the core surface minimal. Secure key-management,
keyed hashing/identifier generation, and authenticated
encryption are defined as an optional I57 secure extension
and are profiled by S57.

============================================================
STATUS OF THIS MEMO
============================================================

This document is provided for informational purposes and is
intended for production use.

============================================================
1. INTRODUCTION
============================================================

I57 defines the integration contract across:

- B57 -> encoding
- H57 -> hash representation
- R57 -> randomness generation
- ID57 -> identifier profile

I57 MUST provide:

- canonical composition
- strict layering
- unambiguous validation behavior
- cross-implementation portability

4. CORE FUNCTIONS
============================================================

4.1 i57_encode

function i57_encode(input_bytes) -> string

Definition:
 return b57_encode(input_bytes)

------------------------------------------------------------

4.2 i57_decode

function i57_decode(input_string) -> bytes | error

Definition:
 return b57_decode(input_string)

------------------------------------------------------------

4.3 i57_hash

function i57_hash(input_bytes, length_enum) -> string

Definition:
 return h57_hash(input_bytes, length_enum)

Notes:

- Hash function selection is implementation-defined and SHOULD
  default to BLAKE3 where available.

------------------------------------------------------------

4.4 i57_random

function i57_random(random_profile_param) -> string

Definition:
 return random_b57_output(random_profile_param)

Notes:

- Some implementations expose R57 mode enums.
- Some implementations expose a profile parameter while still
  requiring canonical R57-compatible output constraints.
- Implementations MAY delegate to r57_generate(mode_enum) or
  MAY generate CSPRNG bytes directly and encode with B57,
  provided output constraints remain R57-compatible.

------------------------------------------------------------

4.5 i57_id

function i57_id(input_bytes, length_enum) -> string

Definition:
 return id57_generate(input_bytes, length_enum)

Notes:

- length_enum MAY be positive (bit length, ID57 Core API 7.1)
  or negative (fixed width, FIXED_k, ID57 Core API 7.2). There
  is no separate short-identifier function; i57_id covers both
  uniformly via the same sign dispatch as id57_generate (see
  ID57 Core API v0.3.0/v0.3.1, sections 5, 7, 10).

5. VALIDATION FUNCTIONS
============================================================

5.1 i57_is_valid

function i57_is_valid(input_string) -> boolean

Requirements:

- MUST validate characters using B57 rules
- MUST reject non-ASCII input
- MUST reject whitespace
- Integration-layer behavior SHOULD reject empty strings

------------------------------------------------------------

5.2 i57_is_canonical

function i57_is_canonical(input_string) -> boolean

Definition:

 decoded = b57_decode(input_string)
 reencoded = b57_encode(decoded)
 return (input_string == reencoded)

------------------------------------------------------------

5.3 i57_validate_identifier

function i57_validate_identifier(input_string, length_enum) -> boolean

length_enum's SIGN selects the check, mirroring ID57 Core API
7.3/11.4/11.5. id57_is_length (ID57 Core API 11.5) is defined
ONLY for fixed widths, so it is used only in that branch; the
bit-length branch is implemented directly here.

Definition:

 if length_enum < 0:                     // FIXED width
     return id57_is_length(input_string, length_enum)

 // bit length - id57_is_length does not apply; validate via
 // canonical decode + byte-length/mask check
 (min_chars, max_chars) = id57_range(length_enum)
 if length(input_string) < min_chars or
    length(input_string) > max_chars:
        return false
 if not id57_is_canonical(input_string):
        return false

 decoded     = b57_decode(input_string)
 bit_length  = bits(length_enum)
 byte_length = ceil(bit_length / 8)
 if length(decoded) != byte_length:
        return false

 excess_bits = byte_length * 8 - bit_length
 if excess_bits > 0:
     last_byte = decoded[byte_length - 1]
     if (last_byte & ((1 << excess_bits) - 1)) != 0:
         return false

 return true

Requirements:

- Fixed widths (negative length_enum): valid B57 AND exact
  length == -length_enum (delegates entirely to id57_is_length;
  MUST NOT decode/check canonical form - fixed-width output is
  a bignum prefix, not canonical B57)
- Bit lengths (positive length_enum): valid B57, canonical,
  within the [min_chars, max_chars] bound (ID57 Core API 7.3),
  and decodes to the correct byte length with correctly masked
  excess bits. Character length MUST NOT be checked for exact
  equality

------------------------------------------------------------

5.4 i57_validate_entropy

function i57_validate_entropy(input_string) -> boolean

Purpose:

- heuristic entropy check (non-security)

Requirements:

- MUST NOT be used for security decisions

------------------------------------------------------------

5.5 i57_validate

function i57_validate(input_string, length_enum?) -> boolean

Requirements:

- MUST enforce valid + canonical behavior for bit lengths, or
  valid + exact width for fixed lengths (via
  i57_validate_identifier, 5.3) when length_enum is provided
- MUST NOT enforce an exact character count for bit lengths;
  MUST enforce one for fixed lengths (sign-dependent, per 5.3)

============================================================
6. OPTIONAL SECURE EXTENSION
============================================================

Some implementations expose an optional secure extension.
S57 profiles this extension as a secure composition layer.

Optional functions:

- i57_resolve_keys(config) -> secure_keys | error
- i57_hash_secure(input_bytes, length_enum, secure_keys) -> string | error
- i57_id_secure(input_bytes, length_enum, mode_enum, secure_keys) -> string | error
- i57_encrypt(plaintext, key, key_id, aad?) -> string | error
- i57_decrypt(encoded, key, expected_key_id, aad?) -> plaintext | error

Binding compatibility note:

- Some language bindings require explicit hash_fn arguments for
  i57_hash and i57_id (with BLAKE3 as default behavior).

Secure extension requirements:

- key material MUST be domain-separated
- key material MUST be treated as secret
- encryption MUST use AES-256-GCM
- authenticated decryption MUST fail closed

============================================================
7. INTEGRATION RULES
============================================================

All outputs MUST follow one of:

Encoding:
 bytes -> B57 -> string

Hash:
 bytes -> HASH -> bytes -> B57 -> string

Random:
 entropy -> bytes -> B57 -> string

Identifier:
 bytes -> HASH -> truncate -> bytes -> B57 -> string

Rules:

- Encoding MUST be B57
- Hashing MUST precede truncation
- Truncation MUST occur before encoding
- Randomness MUST be >=128-bit in security-sensitive contexts
- All outputs MUST be canonical

============================================================
8. INVARIANTS
============================================================

The following MUST hold:

 i57_decode(i57_encode(x)) == x

 i57_encode(i57_decode(y)) == y
 (only if y is canonical)

 i57_hash(x, L) == b57_encode(truncate_bytes(HASH(x), bits(L)))

 i57_id(x, L) == b57_encode(truncate_bytes(HASH(x), bits(L)))

============================================================
9. ERROR MODEL
============================================================

Core errors:

- INVALID_CHAR
- NON_CANONICAL
- INVALID_LENGTH_ENUM
- ENTROPY_FAILURE
- INVALID_MODE

Secure extension errors (if implemented):

- KEY_UNAVAILABLE
- KEY_INVALID
- INVALID_VERSION
- AUTH_FAILURE

Requirements:

- Errors MUST be deterministic
- Implementations MUST fail closed

============================================================
10. PROHIBITED BEHAVIORS
============================================================

Implementations MUST NOT:

- bypass hashing for identifiers
- generate randomness without CSPRNG or approved derivation
- truncate after encoding
- sample B57 alphabet directly
- normalize or transform canonical outputs
- accept non-canonical inputs in strict validation flows

============================================================
11. SECURITY CONSIDERATIONS
============================================================

I57 core provides no guarantees beyond underlying primitives.
Security depends on entropy quality, hash function strength,
and canonical enforcement.

For key derivation, keyed hashing, and encryption profiles,
use S57.

13. REVISION NOTES
============================================================

v1.0.1:

- Aligned with ID57 Core API v0.2.0: i57_validate_identifier
  and i57_validate now take a length_enum and enforce it via
  id57_is_length's [min_chars, max_chars] bound instead of an
  exact character count (the old "expected identifier length
  policy" / expected_length_chars wording implied a fixed
  length, which B57's bignum encoding never guaranteed).
- Noted (4.5) that i57_id already covers the former
  ID57-SHORT lengths directly - ID57-SHORT is merged into
  ID57 Core API and no longer exists as a separate profile.

v1.0.2:

- Aligned with ID57 Core API v0.3.0/v0.3.1: informational bit
  lengths are replaced by fixed widths selected by NEGATIVE
  length_enum values (FIXED_k). id57_is_length is now defined
  ONLY for fixed widths.
- BREAKING: i57_validate_identifier (5.3) and i57_validate
  (5.5) now branch on length_enum's sign. Fixed widths delegate
  to id57_is_length unchanged. Bit lengths NO LONGER delegate
  to id57_is_length (it does not accept them) - the bound +
  canonical + decoded-byte-length check is now implemented
  directly in i57_validate_identifier itself.
- i57_id (4.5) notes updated for the sign-based length model.
