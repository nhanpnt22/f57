============================================================
ABSTRACT
============================================================

R57 Profile defines a standardized set of 128-bit random
generation modes for producing canonical B57-encoded
identifiers for use in H57 and related systems.

It specifies entropy-safe generation pipelines that produce
raw 128-bit values, which are then encoded using B57 into
fixed-length, human-readable identifiers.

R57 ensures strong entropy guarantees, deterministic
encoding, and consistent cross-platform behavior.

============================================================
1. INTRODUCTION
============================================================

R57 defines how 128-bit entropy is generated prior to
B57 encoding.

Pipeline:

 raw_entropy (128-bit) → B57 → identifier string

Goals:

- enforce strict 128-bit entropy
- standardize generation strategies
- ensure interoperability
- prevent biased or weak randomness
- preserve canonical B57 encoding

============================================================
2. SCOPE
============================================================

R57 applies ONLY to entropy generation.

It does NOT define:

- hashing (H57 Core API)
- encoding (B57 Core API)
- truncation (ID57 Core API)

============================================================
3. CORE REQUIREMENTS
============================================================

All modes MUST:

- produce exactly 16 bytes (128 bits)
- generate entropy BEFORE encoding
- avoid modulo bias
- avoid direct alphabet sampling

Encoding:

 output = b57_encode(raw_bytes)

Rules:

- Encoding MUST be deterministic
- Entropy generation MAY be deterministic or non-deterministic
  depending on mode

Output:

- MUST be a 22-character canonical B57 string

Byte Order:

- Raw bytes MUST be interpreted as big-endian

============================================================
4. CRYPTOGRAPHIC REQUIREMENTS
============================================================

- HASH MUST be cryptographic (e.g., BLAKE3, SHA-256, SHA-512)
- KDF MUST be cryptographically secure
- CSPRNG MUST provide ≥128-bit unpredictable entropy

============================================================
5. RANDOM MODES (LOCKED SET)
============================================================

Implementations MUST support the following modes:

------------------------------------------------------------
R57-1-CSPRNG (RECOMMENDED)
------------------------------------------------------------

Definition:
 raw = CSPRNG(16 bytes)

Properties:
- non-deterministic
- fully unpredictable
- maximum entropy

Use:
- default mode for all systems

------------------------------------------------------------
R57-2-HASH-ENTROPY
------------------------------------------------------------

Definition:
 raw = HASH(entropy_input)

Requirements:
- entropy_input MUST be ≥128-bit unpredictable
- HASH MUST be cryptographic

Properties:
- deterministic from entropy source
- uniform distribution

------------------------------------------------------------
R57-3-KDF-DERIVED
------------------------------------------------------------

Definition:
 raw = KDF(secret, context)

Requirements:
- secret MUST be high entropy
- context MUST ensure uniqueness

Properties:
- deterministic
- secret-bound

------------------------------------------------------------
R57-4-COUNTER-KDF
------------------------------------------------------------

Definition:
 raw = KDF(secret, counter)

Requirements:
- counter MUST be strictly increasing
- MUST include secret

Properties:
- deterministic sequence
- collision-resistant (with secret)

------------------------------------------------------------
R57-5-TIMESTAMP-KDF
------------------------------------------------------------

Definition:
 raw = KDF(secret, timestamp || entropy)

Requirements:
- MUST include additional entropy ≥128-bit
- MUST NOT rely on timestamp alone

Properties:
- time-bound
- partially ordered

------------------------------------------------------------
R57-6-HARDWARE-RNG
------------------------------------------------------------

Definition:
 raw = HRNG(16 bytes)

Requirements:
- MUST be cryptographically secure hardware source

Properties:
- high assurance entropy

------------------------------------------------------------
R57-7-UUIDV4-COMPAT
------------------------------------------------------------

Definition:
 raw = UUIDv4_bytes

Notes:
- UUIDv4 provides 122 bits of randomness
- 6 bits are fixed by specification

Requirements:
- Implementations MUST NOT assume full 128-bit entropy
- SHOULD NOT use this mode for high-security contexts

Properties:
- interoperability with UUID systems

------------------------------------------------------------
R57-8-HYBRID-ENTROPY
------------------------------------------------------------

Definition:
 raw = HASH(CSPRNG || HRNG || context)

Requirements:
- MUST include ≥128-bit entropy from CSPRNG
- additional sources MUST NOT reduce entropy

Properties:
- multi-source entropy
- resilient to partial compromise

============================================================
6. INVARIANTS
============================================================

The following MUST hold:

 len(raw_bytes) == 16

 output == b57_encode(raw_bytes)

 b57_decode(output) == raw_bytes

============================================================
7. ERROR MODEL
============================================================

Implementations MUST detect and reject:

- INSUFFICIENT_ENTROPY
- INVALID_MODE
- INVALID_INPUT

Requirements:

- Errors MUST be deterministic
- Implementations MUST NOT continue after failure
- MUST NOT use ambiguous error types

============================================================
8. SECURITY CONSIDERATIONS
============================================================

Security depends on:

- entropy quality (≥128-bit)
- secrecy of inputs (where applicable)
- correctness of implementation

Notes:

- R57-1 provides maximum unpredictability
- Deterministic modes require secure secret handling
- UUIDv4 mode provides reduced entropy (122-bit)

Weaknesses:

- weak RNG compromises all guarantees
- predictable inputs reduce security
- misuse of deterministic modes may leak structure

R57 MUST NOT be used as:

- encryption
- authentication
- randomness generation

============================================================
9. PROHIBITED BEHAVIORS
============================================================

Implementations MUST NOT:

- generate <128-bit entropy
- truncate encoded output
- encode partial bytes
- use modulo-based mapping
- derive entropy from predictable inputs
- mix encoding schemes
- introduce hidden state

============================================================
10. INTEROPERABILITY
============================================================

All implementations MUST:

- produce identical outputs for identical raw bytes
- encode using canonical B57
- preserve byte order (big-endian)

============================================================
11. IMPLEMENTATION NOTES
============================================================

- Raw bytes MUST be generated before encoding
- Systems SHOULD use R57-1-CSPRNG by default
- Deterministic modes MUST include secret input
- Hybrid mode SHOULD be used in high-security systems

============================================================
12. FUTURE EXTENSIONS
============================================================

Reserved:

- R57-D (deterministic-only profiles)
- R57-K (KDF-focused profiles)
- R57-X (experimental modes)
