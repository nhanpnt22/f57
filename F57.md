# F57 - 57 Family

## Tagline

A unified family of secure, deterministic 57-series encodings.

## Description

F57 is the umbrella architecture for the 57-series standards and implementations:

- B57
- H57
- I57
- ID57 (includes short/informational lengths - no longer a separate profile)
- R57
- S57

F57 defines how these profiles fit together as one interoperable system across Go, Rust, JavaScript/Node.js, TypeScript/Node.js, Dart, and Python.

## Purpose

F57 exists to provide one canonical, cross-language foundation for:

- Readable and unambiguous binary-to-text encoding.
- Deterministic hash and identifier surfaces.
- Secure random identifier generation.
- Security composition with domain-separated derivation and authenticated encryption.

## Architecture

F57 is organized into layered profiles with clear boundaries:

1. B57: Canonical encoding layer.
2. H57: Full hash representation layer.
3. ID57: Deterministic identifier profile, spanning both security lengths and
   compact/informational lengths for constrained contexts (short URLs, invite
   codes, etc.) under a single API.
4. R57: Random generation profile.
5. I57: Integration facade profile.
6. S57: Security composition profile.

## Base Layer Policy

B57 remains the canonical base encoding layer inside F57.

- F57 is the umbrella family name.
- B57 is the base primitive and core mathematical layer.

## Versioning Policy

F57 uses two version dimensions:

- Protocol/spec version: the formal specification release (currently v0.1.0).
- Repository release tag: the repository publication tag (currently v0.1.1).

This separation keeps protocol semantics stable while allowing repository-level documentation and release-process improvements.

## Release Consistency Criteria

A release is considered consistent when:

- Specs in `spec/` are the source of truth.
- Language implementations pass their scoped tests.
- Cross-language deterministic parity evidence is current.
- Top-level governance documents agree on release posture.
