# Changelog

All notable changes to the F57 specification family and its associated native implementations will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- TypeScript package release hardening in `implementations/ts`:
  - distributable build output (`dist/` with JS + `.d.ts`)
  - package export metadata (`main`, `types`, `exports`, `files`)
  - release rehearsal command (`npm run verify:all`) and successful `npm pack` packaging flow
- `id57_range(length_enum)` in every language: returns the character bound for a bit
  length (`[min_chars, max_chars]`, since B57 is a bignum encoding and width is never
  fixed for a bit length) or `(k, k)` for a fixed width.
- `id57_is_length(id57_string, length_enum)` in every language: the length-conformance
  check, **defined only for fixed widths** (negative `length_enum`). It checks exactly
  two things - valid B57 alphabet, and exact length `k` - and raises `INVALID_LENGTH_ENUM`
  for any positive/bit-length value (fixed-width output is a prefix of a bignum encoding,
  not canonical B57, so it is never decoded/canonicalized to validate it).
- `i57_validate_identifier(input_string, length_enum)` in every language now takes a
  `length_enum` and dispatches on its sign: fixed widths delegate to `id57_is_length`;
  bit lengths validate via the `[min,max]` bound + canonical decode + byte-length/mask
  check (implemented directly in `i57`, since `id57_is_length` doesn't cover bit lengths).
  Several languages' prior implementation hardcoded an exact `len == 22` check with no
  `length_enum` parameter at all - the same fixed-length assumption this whole change
  corrects; now fixed.

### Changed
- **BREAKING: ID57-SHORT no longer exists, anywhere.** It was a distinct profile/module/
  spec (`id57-short-profile.txt`, `id57_short.*` per language) restricting ID57 to a few
  lengths under separate names/defaults. It is fully merged into ID57 Core API
  (`id57-core-api.txt`, section 10: SHORT-LENGTH USAGE) - `id57_generate`/`id57_verify`/
  `id57_range`/`id57_is_length` already cover short/fixed-width identifiers directly, and
  `id57-short-profile.txt` has been deleted (not just deprecated) from the repository.
  Every language implementation (Go, Rust, TypeScript, Dart, JavaScript, Python) has
  removed its `id57_short`/`ID57Short*`/`id57s_*`-prefixed module, type, and function set;
  callers needing a short/fixed-width identifier call `id57_generate(x, FIXED_8)` (or
  another fixed width, see below) directly on the unified API. No deprecated shims remain.
- **BREAKING: ID57's non-security lengths are now fixed character WIDTHS, not bit
  lengths.** `length_enum`'s **sign** now selects the mode:
  - **Positive** `length_enum` -> bit length (`ID57_LEN_8/16/32/64/128/256/512`, unchanged
    generation algorithm). Character width is a `[min_chars, max_chars]` **bound** - B57 is
    a bignum encoding, so it was never actually fixed, even before this change.
  - **Negative** `length_enum` -> fixed width (`FIXED_2` through `FIXED_12`, magnitude =
    exact character count, all 11 consecutive values defined, no gaps). Generated by
    producing the full `ID57_LEN_128` identifier and cutting it to the first `k`
    characters - always exact, since `LEN_128` output is always >= 16 characters. This is
    the one place ID57 permits post-encoding string truncation, and fixed-width output is
    therefore a *prefix* of a bignum encoding, not canonical B57.
  - This replaces the former informational bit lengths (`ID57_LEN_23/29/47/70/93/186/373`)
    entirely - no bit-length combination can produce an exact character count (the
    achievable maximum jumps from 3 to 5 chars, for example, skipping 4 - shown in
    `id57-core-api.txt` 7.2.1/v0.3.0), so a true fixed width needs this different mechanism.
  - Why fixed widths exist at all: QR code payload budgets, short-URL path segments, and
    fixed-width common identifiers (invite/ticket/order codes, database columns, printed
    labels) all need a *constant* width, which bit lengths structurally cannot guarantee.
  - `i57-core-api.txt` (now v1.0.2) and `s57-security-57.txt` (errata) updated to match;
    S57 continues to use only bit lengths (128/256/512) and never exposes fixed widths.
- Top-level release governance docs (`SECURITY.md`, `BENCHMARKS.md`) updated to describe
  fixed widths instead of "ID57-SHORT", including correcting a benchmark claim that no
  longer holds: fixed widths are cut from the full `LEN_128` `BigInt` encode, so - unlike
  a genuinely short bit-length truncation - they do **not** avoid `BigInt` cost.
- Top-level release governance docs updated to include TypeScript package release posture
  and validation evidence.

## [0.1.0] - 2026-05-20

### Added
- **Core Standard**: Finalized the `v0.1.0 FINAL` specification architecture acting directly beneath the `MINDU` design parameters.
- **Specification Suite**: Fully mapped the protocol stack in the `spec/` directory:
  - `b57-core-api.txt` (Base57 canonical encoding)
  - `h57-core-api.txt` (Hashed Base57)
  - `id57-core-api.txt` (128-bit Identity Generation)
  - `id57-short-profile.txt` (47-bit human-readable IDs)
  - `r57-core-api.txt` (Random generators)
  - `i57-core-api.txt` (Unified facade)
  - `s57-security-57.txt` (Secure composition profile)
- **Language Support**: Released completely native, zero-dependency (other than hashing/math primitives) implementations for:
  - Go
  - Rust
  - JavaScript/TypeScript
  - Dart
  - Python
- **Validation**: Added the `.10k UAT Parity Report` confirming 0 calculation variants across all 5 languages when computing truncations and generating IDs.
- **Governance**: Officially published `README.md`, `RELEASE.md`, `SECURITY.md`, and `BENCHMARKS.md` establishing the formal `v0.1.0` posture.
